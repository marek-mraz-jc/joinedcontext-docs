# App SDK

Family **SDK** (SDK-01…SDK-30, SDK-35…SDK-37). Owning chapter: [Architecture/20-app-sdk.md](../Architecture/20-app-sdk.md). Verified by: [Testing/03-frontend-and-e2e-tests.md](../Testing/03-frontend-and-e2e-tests.md).

Generated `static` applications are code written against one platform package, `@joinedcontext/sdk` ([ADR-N-022](../Decisions/adr-n-022-generated-applications-are-code-on-the-app-sdk.md)). This family defines the package, the template application a generation run starts from (interface, serverless functions and tests), the runtime that executes functions, the one-shot first run, the editing agent that follows and the preview that shows the result. The application rules of [apps.md](apps.md) still hold; this family says how a generated application meets them.

A path written `src/…` or `functions/…` is a path inside the generated application, whose
template is `joinedcontext-portal/sdk/template/`. A path that begins with a repository name is a
path in this platform's own tree.

## 1. The package

- **SDK-01** — The platform MUST ship one TypeScript package `@joinedcontext/sdk`, built from `joinedcontext-portal/sdk/` at the Portal's version, with the entry points `@joinedcontext/sdk` for the interface, `@joinedcontext/sdk/server` for functions and `@joinedcontext/sdk/testing` for tests, through which a generated application does all its data access, identity, function calls and permission checks and gets its design tokens, formatters, form fields, basemap, map worker and exports (ADR-N-022).
- **SDK-02** [S] — The SDK's data client MUST reach only `ngsi-ld/v1/entities`, `ngsi-ld/v1/temporal/entities`, `schema/` and `access` under `/api/endpoint/{slug}/` of the application's own Endpoints and MUST NOT accept a host, a slug or a credential from application code; an application of several endpoints names one by the `name` the served configuration lists (`{ endpoint: "transportation-kpis" }`), a type served by exactly one of them needs no name, and a type served by more than one without a name MUST be refused as a `ProblemError` naming the candidates (AP-04, AP-49).
- **SDK-03** — The SDK MUST return entities as rows flattened from `keyValues` (a GeoProperty as a GeoJSON geometry, a DateTime as its ISO string, a LanguageProperty as the text in the document's language, a Relationship as its URN) and MUST page through the endpoint up to a caller limit of at most 5 000 rows.
- **SDK-04** [H] — Every refusal from the endpoint MUST reach application code as a `ProblemError` carrying the RFC 7807 `status`, `title` and `detail`, and the template's `EntityForm` MUST show that detail without reloading the page (AP-62).
- **SDK-05** [S] — The SDK MUST write only by `create`, `update` of attributes and `remove` through the endpoint, and `create` MUST mint the id `urn:ngsi-ld:{Type}:{orgDomain}:{space}:{localId}` from the served configuration when the application gives a local id.
- **SDK-06** [S] — The SDK MUST take its transport from the document the Portal serves and never from application code: same-origin `fetch` with the platform session and CSRF header for a published application (functions at `/apps/{name}/api/functions/{fn}`), and a `jc-request` message to the framing page for every read, write and function call in the sandboxed preview (AP-63).
- **SDK-07** [H] — `useAccess()` MUST answer `can(operation, type, attr)` from the endpoint's effective grant document (EP-55) with a reason when the answer is no, so a generated control is disabled with that reason (UI-44).
- **SDK-08** [H] — The template MUST carry, as its own source files under `src/components/` that the model may change, React 19 components for an application shell with page navigation and an error boundary, stat tiles, a sortable paged table, an `EntityMap` on MapLibre with the basemap route (AP-67) and a deck.gl overlay for 50 000 features or more and for aggregation (ADR-N-011), bar, line, pie and time-series chart cards on Apache ECharts, an entity detail, an `EntityForm` grounded in the endpoint's JSON Schema (AP-61), a filter bar with search, select, range and date-range filters, and export buttons for CSV, GeoJSON, PDF and PNG (AP-66); the SDK MUST provide the exports, form fields, formatters, basemap style and map worker those components use, and MUST bundle ECharts, Recharts, MapLibre and deck.gl so application code can use them directly.
- **SDK-09** [A] — The SDK MUST carry `API.md`, listing every export of its three entry points with its signature and a one-line purpose in at most 12 000 tokens, and its type declarations, and the first run MUST put both in the model's pack (AP-58).

## 2. The template application

- **SDK-19** [H][P] — `sdk/template/` MUST be a complete application whose tests pass: an interface that renders for any endpoint from its schema alone (an overview of stat tiles and charts, one page per published entity type with a filter bar, table, map, chart, detail and, when the confirmed data needs grant a write, an edit form), at least one function, and vitest tests for its pages and functions, so a generated application changes or adds a few files instead of writing a whole one.
- **SDK-25** [H] — The template MUST carry `src/design-tokens.json` (colours, typography, spacing, radii, chart palette, map colours), from which the SDK MUST derive its CSS variables, the ECharts and Recharts themes and the map's point and layer colours at start, so editing that one file re-themes the whole application; the file MUST be writable by the model and by a person, and the Portal MUST seed it from the installation's branding when one is configured.
- **SDK-10** [A] — The Portal MUST obtain `src/jc-types.ts` for every run from Model Tools, which MUST render it with LinkML's `gen-typescript` from the projected `model.linkml.yaml` of every endpoint of the run that serves a needed type, one declaration per name across them, with the NGSI-LD kinds mapped to the row shape of SDK-03, as type-only declarations assignable to the SDK's row type with an `id` and literal `type` on every entity type, and the model MUST NOT write it (DM-19, MP-03).
- **SDK-11** [A][S] — The Portal MUST apply model output only to `src/**/*.tsx`, `src/**/*.ts`, `src/**/*.css`, `src/design-tokens.json` or `functions/**/*.ts` other than `src/main.tsx` and `src/jc-types.ts`, up to 80 files and 800 KB in total, and MUST refuse and report every other path as a run event (AP-58, AG-39).
- **SDK-12** [S] — The Portal MUST refuse, before a preview exists, any import other than: in interface code a relative file, `react`, `react-dom/client`, `react/jsx-runtime`, `echarts`, `recharts`, `maplibre-gl`, `@deck.gl/core`, `@deck.gl/layers`, `@deck.gl/aggregation-layers`, `@deck.gl/mapbox` or `@joinedcontext/sdk`; in a function a relative file under `functions/` or `@joinedcontext/sdk/server`; in a test additionally `vitest`, `@testing-library/react` or `@joinedcontext/sdk/testing`; and a type-only import anywhere in the project; and MUST hand the refusal back to the model (AP-49, AP-65).

## 3. The first run and the editing agent

- **SDK-13** [A] — The first run MUST be two model calls over the same pack, which holds every template file (interface, functions, tests, `package.json`), the SDK's `API.md` and type declarations, `jc-types.ts`, the confirmed data needs, the effective access of every endpoint of the run, each endpoint's name, context space and served types, five entities per type read through the endpoint that serves it and the prompt: the first MUST ask for a first version, `src/App.tsx`, the application's design and the one page the request is most about, without tests, in an answer of at most about 6,000 tokens, so its preview is on screen within the time of SDK-15; the second, sent as soon as that version is on screen, MUST ask for the rest of the application the data needs support, every page, function, filter, chart, form and export the prompt and the data call for, with a test for every page and function the application has (AP-58).
- **SDK-26** [P] — The first run MUST call the model of the run's `AgentProfile` with its `reasoningEffort` (AG-72), and the reference installation's `app-builder` profile MUST name `google/gemini-3.8-flash` with `reasoningEffort: medium` for it.
- **SDK-27** [A] — Once a preview version has rendered and its requests have settled, the SDK in the frame MUST visit each page the application's navigation offers (the links and tabs inside its `nav` elements), return to the page the person was on, and post one `jc-observation` for that version holding, per page, its label, its visible text (at most 20,000 characters) and the row counts of its tables, plus every request the bridge answered with a 4xx or 5xx status; the host page MUST relay the first observation of each preview version to the run (API/04 §5).
- **SDK-28** [A] — After every generated version the Portal MUST verify it against the run: the runtime errors and failed function calls since that version, the failed requests and the visible text of the observation (`NaN`, `undefined`, `[object Object]`, `Invalid Date`, an entity id `urn:ngsi-ld:…` where a name belongs, and the SDK's `NO_LOCATIONS` sentence while a sampled entity carries a location), and, for every entity type of the data needs, whether a sampled entity's name or local id appears on some page; problems MUST go back to the model as a verification pass, at most three after each instruction, whose version replaces the preview only when it transpiles; a clean check MUST be one line on the conversation naming the pages and the entities it saw; and a person's message MUST be handled before a pending verification pass.
- **SDK-14** [A] — A transpile error, a refused import or the first runtime error the preview reports in the first run MUST go back to the model once with file, line and message, and a second failure MUST end the first run with the errors on the conversation; the template is the model's context and never the preview, so until a generated version transpiles the frame MUST show the run's building state (what it is doing, the entities it read, the errors of a failed attempt) and never the template or a version that failed (AP-59).
- **SDK-20** [A][S] — Every instruction after the first run MUST be handled by an editing agent in the Portal process whose only tools are `list_files`, `read_file`, `edit_file`, `write_file`, `delete_file`, `check`, `call_function`, `preview_errors` and `finish` over the run's files, which MUST stop at `finish`, at the profile's step limit (AG-25) or at the instruction's ceiling of 12 model calls and 500,000 input tokens, saying on the conversation what it spent and what is on screen, which MUST NOT resend a tool result whole once two later model calls have been made, whose every model call MUST be a `usage` event with its input and output tokens, whose every tool call MUST be a run event, and whose writes outside SDK-11 or imports outside SDK-12 MUST be refused as tool errors (AP-60).
- **SDK-15** [P] — The building state MUST be on screen within 5 seconds of the request, the first run's generated preview within 40 seconds on the reference installation, and transpiling 80 files MUST take less than one second (AP-57).
- **SDK-16** [S] — The preview MUST be one document in the sandboxed frame (AP-50) whose modules are the transpiled files and the SDK runtime embedded in the Portal, loaded through an inline import map, under a policy that allows scripts only by hash and the `data:` modules the Portal wrote and `connect-src` only for the basemap route (AP-67).
- **SDK-17** — The first run and each finished agent turn MUST commit the files they changed to the run branch (AP-24, AP-46), and publication MUST build the committed project in the build lane (AP-80) with the SDK version pinned in its `package.json`, never publish the preview's transpiled modules (AP-11).
- **SDK-18** [S] — The host page MUST accept a `jc-request` only from the frame it created: reads under `/api/endpoint/{slug}/` of any endpoint of the run always, writes there only for operations the run's confirmed data needs name, and `/functions/{fn}` only for a function the run's files hold; it MUST perform the request with the reviewer's session, and MUST drop and count every other message without forwarding it (AP-63).

## 4. Functions

- **SDK-21** [A] — A function MUST be one file `functions/{name}.ts`, `name` matching `[a-z][a-z0-9-]{0,39}`, whose default export takes an `FnRequest` (`method`, `query`, JSON `body`, `user`) and an `FnContext` (`jc`, `log`) and returns an `FnResponse` (`status`, JSON `body`), with no runtime-specific API, so the same file runs in vitest against `fakeContext` and in the platform runtime.
- **SDK-22** [S] — The `jc-functions` runtime MUST execute every invocation in a fresh QuickJS context holding only the function's transpiled files, with 64 MiB of memory, 5 seconds of execution, a 256 KiB request and a 1 MiB response, no `fetch`, file system, environment, timer beyond the call or state between calls, and `ctx.jc` as its one host capability, which MUST call the application's endpoint through the Context Gateway with the caller's token (anonymously for a public application) so a function never reads or writes more than its caller may (GW10, AP-16).
- **SDK-23** [S] — The runtime MUST hold no credential, database connection or application code of its own and MUST be reachable from the Portal only; the Portal MUST invoke it for the preview from `POST /api/v1/projects/{project}/agent-runs/{id}/functions/{fn}` with the run's current functions and the reviewer's token, and for a published application from the edge route `/apps/{name}/api/functions/{fn}` with the published build's functions and the `X-Access-Token` the edge set (AP-28).
  > Note: The published half is AP-84, `POST /apps/{name}/api/functions/{fn}` on the static host; it is not built yet (T-2594), and `src/apps/static_host.rs` serves no functions route today.
- **SDK-24** — Publication MUST run the application's interface and function tests in the build lane (AP-80) and MUST refuse to publish when one fails (AP-11).

## 5. The Entity Grid in the SDK

- **SDK-29** — The App SDK MUST export the entity grid, its configuration type and JSON Schema, its data-source interface with the two built-in sources (an Endpoint by slug, a Context Space surface), and its headless hook, documented in `sdk/API.md` with a runnable example, under the same versioning as the rest of the SDK.
- **SDK-30** — An application `spec.json` and a Dashboard MUST be able to place the grid as a view (`kind: "grid"`) with that configuration object.

## 6. The person and their roles

- **SDK-35** [S] — `me()` and `useMe()` MUST return the `user` of the served configuration, `{id, name, email, roles}` or `null` for an anonymous visitor, and MUST NOT fetch, decode or store a token (AP-95).
- **SDK-36** [H] — When `useAccess().can()` answers no to a person who holds roles in the application, its reason MUST name them, "your role viewer does not permit updateAttrs on Alert", so a generated control is disabled with that sentence (SDK-07, UI-44).
- **SDK-37** [S] — A function MUST receive in `request.user` the same `{id, name, email, roles}` the page was served, set by the static host from AP-92 and never from the caller's body or headers (SDK-21, AP-95).
