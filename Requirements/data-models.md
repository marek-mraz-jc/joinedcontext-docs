# Data Models & the LinkML Editor

Family **DM** (DM-01…DM-73). Owning chapter: [11-data-models.md](../Architecture/11-data-models.md). Verified by: [02-conformance-tests.md](../Testing/02-conformance-tests.md).

This chapter specifies how data models are authored, imported, generated, versioned and consumed. The architecture is in [Architecture/11-data-models](../Architecture/11-data-models.md); the decision in [ADR-N-010](../Decisions/adr-n-010-linkml-data-models.md). Requirement family **DM-01…DM-73**. Consumer classes per `00-index.md`.

## 1. Source of truth and artifacts

- **DM-01** — The single authoring format of a data model MUST be LinkML YAML stored at `projects/{p}/spaces/{s}/datamodels/{name}.linkml.yaml`, one per space (DM-61); a space that still holds more than one such file is migrated by `jcctl model merge` (DM-62). JSON Schema, `@context`, documentation and examples are generated artifacts, never hand-edited.
- **DM-02** — Generated artifacts MUST be committed next to the source in the same commit (`json-schema/{name}.v{major}.json`, `context/{name}.v{major}.jsonld`, `docs/{name}.md`, `examples/{name}.example.jsonld`) (CC-25). CI MUST regenerate and fail the merge request on any diff between committed and regenerated output.
- **DM-03** — The JSON Schema dialect MUST be draft-07 (CC-12, stack verdict S4). Generators MUST NOT emit 2019-09 or 2020-12 keywords.
- **DM-04** — Every slot MUST carry an IRI (`slot_uri`) and every class a `class_uri`; a model without complete IRI bindings MUST NOT reach `published` status. Organisation-local terms MUST use the organisation's own namespace prefix, never the Smart Data Models or ETSI prefixes. A slot or class added locally without an IRI (the editor, the assistant's `addSlot`/`addClass` operations, AG-77) MUST be minted under the model's own prefix: the prefix named after the model, `{model name}: {model id}/`, declared in `prefixes` when the model has none yet, so a model whose `default_prefix` is an imported vocabulary (`sdm`) never mints a local term there (DM-16).
- **DM-05** — The NGSI-LD kind of a slot (Property, GeoProperty, Relationship, LanguageProperty, ListProperty, JsonProperty, VocabProperty) MUST be declared with the LinkML annotation `ngsi_ld_kind`, chosen by the shape of the data as [Architecture/11 §1.1](../Architecture/11-data-models.md#11-which-kind-an-attribute-is-by-the-shape-of-its-data-dm-05) sets out. The `@context` generator MUST render the entry each kind asks for: `@type: @id` for a Relationship, `@container: @language` for a LanguageProperty, `@type: @vocab` for a VocabProperty, `@container: @list` for a ListProperty and `@type: @json` for a JsonProperty; a Property and a GeoProperty carry the term's IRI alone. The kind itself MUST NOT appear in the term definition, which JSON-LD 1.1 would reject, and travels as `x-ngsi-ld-kind` in the JSON Schema instead.
- **DM-06** — Units MUST be declared with UN/CEFACT common codes (`unit.ucum_code` or `unit.symbol` with the CEFACT code in `unit.exact_mappings`) so exports (CSV/XLSX headers) and dashboards can display them, and NGSI-LD carries that code as the attribute's `unitCode` (DM-59).
- **DM-60** [A] — A Context Space MAY declare a **Data Structure Definition**: a `DataModel` whose class is annotated as the DSD, whose dimension slots are `VocabProperty` or `Relationship` and whose measure slots are `Property` with a unit (DM-05, DM-59). An observation of such a DSD MUST be an ordinary NGSI-LD entity of the project's indicator space carrying one value per dimension and per measure, so every surface an entity already has — endpoint, policy, filter, export — serves it unchanged; the rendered artifacts of a model carrying a DSD MUST include `model.qb.ttl`, the RDF Data Cube rendering an SDMX consumer reads. A single-value indicator stays `KeyPerformanceIndicator` (PF-55): the cube is for an indicator whose dimensions are questions of their own, and [Architecture/03 §2](../Architecture/03-domain-model.md#when-one-number-is-not-the-indicator-dm-60) says which is which.
- **DM-59** [A] — A unit MUST also carry its QUDT anchor: the QUDT unit IRI in `unit.exact_mappings` beside the UN/CEFACT code, and, where the vocabulary has one, the quantity kind in `unit.has_quantity_kind` (`qudt:hasQuantityKind`). The UN/CEFACT code is the wire value and says nothing a machine can resolve; the QUDT IRI dereferences, carries `qudt:ucumCode` and names the dimension, which is what lets a federated read align two organisations' measurements rather than compare two opaque codes. Every prefix these mappings use MUST be declared in the model's `prefixes`, so the CURIE a reader of the rendered artifacts finds resolves; a mapping under an undeclared prefix MUST fail generation. The crosswalk from a picked unit to its QUDT IRI lives in the editor's unit table and nowhere else: the model records the choice and every generator reads the model (DM-01).

## 2. Import from Smart Data Models (primary path)

- **DM-07** [H][A] — The Portal MUST offer an import wizard that browses the Smart Data Models catalogue by subject and model and imports a model with its `schema.json`, `context.jsonld`, `model.yaml` and normalized example.
- **DM-08** — Import MUST record provenance in the model metadata: repository, path and commit of every fetched artifact (`spec.source.{repository,path,commit}`), so a re-import is reproducible and a diff against upstream can be shown later.
- **DM-09** — Conversion MUST use LinkML schema-automator (`import-json-schema`) followed by the platform post-processor that binds `slot_uri`/`class_uri` from `context.jsonld`, carries descriptions, enums and units, and maps `id`, `type`, `location`, `observedAt` to the shared `ngsi-ld-core` import.
- **DM-10** — Fetching MUST be performed server-side by Model Tools with an allowlist restricted to the Smart Data Models organisation; the browser MUST NOT fetch third-party schemas directly.
- **DM-11** — An imported model MUST keep every upstream slot; slots the user does not use MUST be marked `deprecated: true` rather than removed, so payloads of federation partners still validate.
- **DM-12** — The catalogue index MUST be cached by Model Tools with a daily refresh and an explicit "refresh now" action; catalogue unavailability MUST degrade to the cached index, never block editing.

## 3. Authoring (secondary path)

- **DM-13** [H] — The editor MUST provide a structured view (classes, slots, enums) and a YAML source view editing the same document; both views MUST stay synchronised on every change.
- **DM-14** [H] — The YAML view MUST validate and autocomplete against the LinkML metamodel JSON Schema; structural errors MUST be shown inline with line numbers.
- **DM-15** [H] — Titles and descriptions of classes and slots MUST be language maps covering every locale configured for the organisation; missing locales MUST be flagged before publishing (yellow lane may auto-fill via the translation blueprint with `machineTranslated: true`).
- **DM-16** — The editor MUST NOT allow a slot IRI under the Smart Data Models, ETSI or W3C namespaces to be minted for a locally added slot (DM-04).

## 4. Generation and preview

- **DM-17** [H][A] — On every change the editor MUST show a live preview of: JSON Schema, `@context`, example entity, rendered form, filter/layer options, documentation and the structural diff against the previous published version.
- **DM-18** — Generation MUST run in Model Tools (versioned OCI image: `linkml`, `schema-automator`, `pysmartdatamodels`, the `ngsi_ld_kind` post-processor). Model Tools MUST be stateless, hold no credentials, read no platform state and have no network egress beyond the DM-10 allowlist.
- **DM-19** — CI MUST invoke the same Model Tools image version as the Portal preview; the image tag is pinned in `platform-settings.yaml` and changes are red-lane.
- **DM-20** — Slot classification for dashboards MUST be derived from the LinkML range: numeric ranges → range filter and `sizeBy`; enums → select filter and `colorBy`; `datetime`/`date` → temporal filter; `ngsi_ld_kind: GeoProperty` → map layer geometry; Relationships → link picker.
- **DM-21** — The example entity MUST validate against the generated JSON Schema and expand without warnings against the generated `@context`; CI MUST assert both.

## 5. Versioning and lifecycle

- **DM-22** — Every model version MUST carry a semantic version; published versions are immutable and served at `schema/v{major}/…` (SP-13).
- **DM-23** — The editor MUST classify a change as additive (new optional slot, new enum value, text) → minor, or breaking (removed/renamed slot, narrowed range, new required slot, changed IRI) → major, and MUST refuse to save a breaking change under the current major version.
- **DM-24** — Lane assignment: draft model → green; additive change to a published model → yellow; breaking change or change to a model referenced by a public endpoint → red (CC-63).
- **DM-25** — Before publishing a new major version the editor MUST list all consumers of the previous version (endpoints, pipelines, dashboards, subscriptions, registrations) and CI MUST block deletion of a version that is still referenced.
- **DM-26** — Lifecycle states MUST be `draft → published → deprecated → retired`; only `published` models may be referenced by endpoints and pipelines; `retired` models remain resolvable at their versioned URLs.

## 6. Enforcement at the gateway

- **DM-27** — The Context Gateway MUST validate create/update payloads against the space's published JSON Schema versions; violations return 400 with RFC 7807 details naming the failing keyword and path.
- **DM-28** — Payloads with undeclared attributes MUST be rejected unless the model declares `open_world: true` on the class.
- **DM-29** — The gateway MUST serve `@context` documents only from the committed artifacts (hardened context cache, R58); a `Link` header pointing elsewhere is expanded but never trusted for validation.

## 7. Agents and programs

- **DM-30** [A] — `describe_schema` on the data MCP MUST return the published LinkML-derived JSON Schema, the `@context` URL, slot titles in the caller's language, units and the NGSI-LD kind per slot.
- **DM-31** [A][P] — Model changes proposed by agents or programs MUST follow the same lanes as human changes (DM-24); an agent MUST NOT publish a model directly.
- **DM-32** — `jcctl model {import,generate,diff,validate}` MUST expose every editor capability on the command line with JSON output, so CI, agents and the Portal share one implementation.

## 8. Mappings (LinkML-Map) and transformations

- **DM-33** — Model-to-model transformations MUST be declared as `kind: Mapping` whose `spec.transformation` is a verbatim LinkML-Map `TransformationSpecification`, with `spec.source` and `spec.target` referencing published DataModel versions; JSONata, jq, JMESPath or JavaScript MUST NOT be introduced as mapping languages.
- **DM-34** — Model Tools MUST validate every Mapping against both referenced schemas at authoring time and in CI: unknown source slots, unpopulated required target slots, type mismatches, undeclared units in `unit_conversion`, and enum values outside the target `permissible_values` are errors.
- **DM-35** — Model Tools MUST compile every valid Mapping to a Bloblang mapping committed at `generated/{name}.blobl` beside the specification, together with a compile report (derivation → Bloblang line); CI MUST fail on any diff between committed and regenerated output (as DM-02).
- **DM-36** — The compiler MUST support: `populated_from` (including nested paths), `expr` with arithmetic, concatenation and comparison, `value_mappings`, `unit_conversion`, `cast`, `range` coercion, `hide`/`derived_from` for dropped slots, and class-level `populated_from` with `joins` on single-valued references. Any other construct MUST fail compilation with a message naming the derivation; silent fallback is forbidden.
- **DM-37** — Bento remains the only transformation runtime and Bloblang the only runtime language: a `Pipeline` uses a Mapping through `spec.mappingRef` and the reconciler injects the compiled Bloblang as a `mapping` processor; the LinkML-Map specification itself is never interpreted at runtime.
- **DM-38** — A Mapping MAY contain `native: bloblang` blocks for logic LinkML-Map cannot express; each block MUST be attached to one target slot, MUST be listed in the compile report as "unchecked", MUST raise the lane by one level (green→yellow, yellow→red), and MUST be shown in the editor with a distinct marker. Aggregation across collections, grouping and joins on multivalued references MUST live in the pipeline's own Bloblang or in code, not in a Mapping.
- **DM-39** — Every Mapping MUST carry at least one golden test (`spec.tests[]`: input example → expected output) that CI executes both through Model Tools (specification semantics) and through `bento test` (compiled Bloblang); the two results MUST be identical, which is the compiler's own correctness gate.
- **DM-40** [H] — The LinkML Editor MUST offer a *Mappings* tab that pre-fills `slot_derivations` from identical slot names, `exact_mappings`/`close_mappings` and SSSOM alignment sets, shows the transformed example and the derived target-schema diff live, and refuses to save a Mapping that fails DM-34.
- **DM-41** — `jcctl model migrate --mapping {name} --space {space}` MUST apply a compiled Mapping to existing entities of a space through the gateway (never directly against the broker), in batches with a plan (count of entities per type) shown first and a dry-run mode; it MUST be used for major-version migrations (DM-23) and recorded as a repository change.
- **DM-42** — Vocabulary alignments between models MUST be stored as SSSOM mapping sets (`datamodels/alignments/*.sssom.tsv`), served at `/cs/{space}/schema/alignments/`, mirrored into the slots' `exact_mappings`/`close_mappings`, and used only for editor pre-fill and documentation; SSSOM sets MUST NOT be executed as transformations.

## 9. Rendered schema artifacts and the artifact store

- **DM-43** — For every published DataModel version Model Tools MUST render, from the LinkML source: JSON Schema draft-07 (`gen-json-schema`), `@context` (`gen-jsonld-context` + `ngsi_ld_kind` post-processor), SHACL shapes (`gen-shacl`, closed shapes unless `open_world: true`, `sh:datatype`/`sh:in`/`sh:minCount` derived from ranges, enums and `required`), OWL (`gen-owl`, Turtle), RDF renderings of the schema (`gen-rdf`, Turtle/JSON-LD/N-Triples), Markdown documentation (`gen-doc`) and the validated example entity; the set MUST be produced in one run with one recorded generator version so the artifacts are mutually consistent.
- **DM-44** — The DM-02 set (JSON Schema, `@context`, docs, example) remains committed in Git; the full rendered set MUST additionally be uploaded to the artifact store under `schemas/{org}/{project}/{space}/{model}/v{major}/{artifact}` with `index.json` (sizes, sha256, generator versions, source commit) by `jcctl apply` after merge. The store is derivative: `jcctl artifacts rebuild --repo-dir {checkout} --out-dir {dir} [--space {s}]` MUST regenerate every artifact from Git and MUST produce byte-identical output for the same source commit and generator version (CI asserts this on a sample).
- **DM-45** — Endpoint projections (EP-47) MUST be rendered per (endpoint, model version, policy digest) and stored under `endpoints/{slug}/schema/v{major}/`; a Policy change that alters the readable set MUST trigger re-rendering in the same reconcile and MUST invalidate the previous objects.
- **DM-46** [A] — The data MCP of a space and of an endpoint MUST expose the rendered artifacts as MCP resources (`schema://…`, EP-52) and `describe_schema` MUST accept `format`; the SHACL artifact MUST be usable directly by a consumer's own validator (pySHACL, TopBraid) against `ngsi-ld/v1` responses expanded with the served `@context`, and CI MUST prove this with pySHACL on the example entity for every published version.
- **DM-47** — Artifacts of `published`, `deprecated` and `retired` versions MUST stay resolvable and byte-stable at their versioned paths (DM-26); the store MUST enforce write-once for `v{major}/` prefixes (object lock or bucket policy) so a re-render can only add a new `index.json` revision, never replace a published artifact in place.

## 10. Federation: foreign models and cross-space mappings

- **DM-48** — When a `SharedSpaceReference` or a `ContextSourceRegistration` targets a remote endpoint (this instance or another), the reconciler MUST fetch `schema/index.json`, `model.linkml.yaml`, `context.jsonld` and `example.jsonld` under that endpoint's schema surface (EP-46) for every exposed model version and commit them as **foreign DataModels** (`spec.source.remote: { url, version, sha256, fetchedAt }`, lifecycle `mirrored`), in the same change as the reference; a peer without a schema surface MUST be flagged in the plan and MAY still be referenced without a model.
- **DM-49** — Foreign DataModels MUST be read-only in the editor, MUST NOT be referenced by local Endpoints as their own model, and MUST be re-fetched on the reference's `schedule` (default 24 h); a changed sha256 MUST open a merge request showing the schema diff and listing local Mappings that reference the model (DM-25 spirit).
- **DM-50** — The editor MUST offer "Map to local model" on a foreign model and "Map from local model" on a local one, producing an ordinary `kind: Mapping` (DM-33…DM-42) whose golden test defaults to the peer's `example.jsonld`.
- **DM-51** — A `ContextSourceRegistration` MAY carry `spec.mappingRef`; the Context Gateway MUST then translate federated responses through the Mapping and rewrite outgoing `attrs`, `q`, `geoQ` attribute names and enum values through its inverse. Live translation MUST accept only the invertible subset (`populated_from` renames, `value_mappings`, linear `unit_conversion`, `cast`); `expr` slots MUST be returned but marked non-filterable in the projected schema; `native` blocks MUST be rejected at apply time with a message pointing to replicate mode.
- **DM-52** — Model Tools MUST compile every Mapping to two artifacts from one specification: Bloblang (DM-35) and a gateway **mapping IR** (JSON, versioned schema); the golden tests (DM-39) MUST pass identically through Bento, the gateway IR interpreter and Model Tools, and CI MUST fail on any divergence.
- **DM-53** — Replicate mode (a Bento pipeline reading the peer endpoint and writing local entities through a Mapping) MUST be the recommended path when the Mapping is not invertible or the peer's latency or availability is not acceptable for live queries; the blueprint `replicate-from-endpoint` MUST render pipeline, Mapping skeleton and foreign model import in one change.

## 11. Inference from a sample

- **DM-54** [H][A] — Model Tools MUST infer a draft LinkML model from a sample a person drops: a CSV or Excel sheet, a JSON document or array, or a PDF's tables; one class per sheet or top-level object, one slot per column or key with its `range` inferred from the values (`integer`, `float`, `boolean`, `datetime` for RFC 3339 and common date forms, `string` otherwise), a `pattern` where every value matches one obvious form, `minimum_value` and `maximum_value` for numbers, a `GeoProperty` kind for a latitude/longitude pair or a GeoJSON value, a unit as a UN/CEFACT common code where a column name or header carries one (DM-06), and every slot aligned with the Smart Data Models catalogue when an attribute of the same name exists there, binding its `slot_uri` (DM-07, MIM2-R1). The answer MUST be the LinkML source and the same model as an ordered list of editor operations (`addClass`, `addSlot`, `setSlot`, `addEnum`, `addEnumValue`, DM-13), so the visual editor applies it as if a person had clicked, and MUST say which slots it could not type and why.
- **DM-55** [S] — A sample is parsed in memory, once, by Model Tools alone: at most 10 MiB, no file written, no external entity resolved (Excel and PDF parsers with XML external entities and remote references disabled), no network call during parsing; the catalogue lookup of DM-54 reads the local index only. A column header or a key is text: it MUST be reduced to a LinkML name (`^[A-Za-z_][A-Za-z0-9_]*$`) with the original kept as the slot's `title`, and it MUST never reach the editor or a browser as markup. The inferred model is a draft in the editor, proposed through the ordinary lane (DM-24, DM-31, CC-71); nothing is published by inference.

## 12. Saving a model

- **DM-56** [H][A] — The source of a model is read and saved through one route of the Portal, scoped to the file DM-01 names and to nothing else: `GET /api/v1/projects/{p}/datamodels/{name}/source` answers the LinkML text at the manifest's `spec.linkml`, and `PUT` on the same route with the new text creates a `Change` (MF-12, CC-32) whose commit carries the source, the manifest with the version the editor computed (DM-22), and the artifacts Model Tools renders for it (DM-02), in the lane DM-24 assigns; a `PUT` is the same call whether a person, the assistant or a program makes it (DM-31). `spec.linkml` stays a relative path ending `.linkml.yaml` under the space's `datamodels/` folder; a manifest MUST NOT carry the document inline, and the route MUST refuse a path outside that folder, a manifest in another project, and a breaking change under the same major version (DM-22, DM-25).
- **DM-57** [H][A] — A model that the project does not hold yet is created through the same route: a `PUT …/datamodels/{name}/source?space={space}` for a name no manifest in the project carries MUST create the DataModel — a manifest with `contextSpaceRef: {space}`, `spec.linkml: ./{name}.linkml.yaml` and the classes of the text — together with the source and the artifacts, in one `Change` whose lane is the green one a draft gets (DM-24). The route MUST refuse a create without a `space`, a `space` the project does not hold, and a name that is not a DNS-1123 label (PF-09); a `PUT` for a name the project does hold stays the update of DM-56, whatever `space` says. A model inferred from a sample (DM-54) therefore reaches the repository through one call, with no path of its own (DM-31, CC-32).
- **DM-58** [H][A] — A slot that binds a term this platform did not define — a `slot_uri` from Smart Data Models, INSPIRE, XÖV or another organisation's model (DM-07, DM-08) — MUST NOT redefine it: its `range`, `unit`, `multivalued`, `required` and, for an enum, its permissible values MUST be the upstream term's, and a local addition MUST get an IRI in the project's own namespace. A slot that means something near but not the same MUST carry its own IRI and record the relation as SSSOM (`skos:closeMatch`, `skos:narrowMatch`, DM-42) rather than claim `exact_mappings` to the upstream term. `jcctl model validate` MUST check every bound `slot_uri` against the upstream artifact the model's provenance names (DM-08) and MUST fail on a redefinition, naming the slot, the term and the field that differs; a model whose upstream artifact is not resolvable MUST be reported as unchecked rather than passed. Reuse is add-only: a model may add terms of its own beside a borrowed one, never change what the borrowed one means (MIM2-R1).

## One model per space

Decided in [ADR-N-033](../Decisions/adr-n-033-one-data-model-per-space.md) (T-2698).

- **DM-61** [S] — A Context Space MUST have exactly one `DataModel`, named by the space's `spec.dataModelRef`; its classes are the space's types, validation MUST refuse a second model file in a space, and the Context Gateway MUST refuse a write of a type the model does not declare. The model MAY `import` published models at a pinned version.
- **DM-62** — Creating a Context Space MUST create its model in the same Change, empty or importing the models picked; `jcctl model merge` MUST merge several models of one space into one, keeping class names, slot IRIs and `class_uri`s, and MUST refuse a clash naming both classes.
- **DM-63** [S] — `GET /api/v1/organization/datamodels?search=` MUST answer every model the caller may read that is not retired (name, project, space, version, lifecycle, classes) and the Smart Data Models catalog entries matching the search, and nothing the caller cannot read ([API/01](../API/01-portal-api.md)).

## 13. Relationships, strict like foreign keys

Owner, 2026-09-24 (T-2735). A relationship between two classes of a model behaves like a foreign key in a database: declared on both ends, one cardinality, one delete rule, one stored copy, and refused when it is wrong, at save and at every write. The architecture is [11-data-models.md §1.2](../Architecture/11-data-models.md#12-relationships-between-classes-dm-64dm-73).

- **DM-64** — A relationship MUST be declared as a pair of slots: the source slot on class A with `range: B` and the inverse slot on B with `range: A`, each naming the other in `inverse:`, each with `inlined: false`, `annotations.ngsi_ld_kind: Relationship` and a `slot_uri` under the model's namespace. B MUST be a class of the model or of a model it imports, and a class MAY relate to itself (`Person.manager` with the inverse `Person.reports`). The source slot MUST be the end that carries `annotations.on_delete`, or, when neither end does, the end declared first under `slots`; the editor MUST write `on_delete` on the source of every relationship it creates, so the direction never rests on order.
- **DM-65** — The cardinality, read from A to B, MUST be stored only as `multivalued` on the two slots: one-to-one when neither is multivalued, one-to-many when only A's slot is, many-to-one when only B's slot is, many-to-many when both are. `required` on an end MUST mean at least one target (UML `1` or `1..*`) and MUST be allowed only on the end that is stored (DM-67): a computed end cannot be satisfied by the write that creates its entity.
- **DM-66** — Each relationship MUST carry one delete rule, `annotations.on_delete` on the source slot: `restrict` (the default when absent), `cascade` or `set-null`. The rule MUST say what happens to the entities that store a reference when the entity they reference is deleted: `restrict` refuses the delete while any reference exists; `cascade` deletes the referencing entities of a single stored end, and removes only the one link instance (its `datasetId`) of a many-to-many end; `set-null` removes the reference, the whole attribute of a single end or the one instance of a many-valued end. A `cascade` or `set-null` that would leave a `required` end empty MUST be refused as `restrict` refuses.
- **DM-67** [S] — Exactly one end of a relationship MUST be stored, as the NGSI-LD Relationship attribute a foreign key would be: for many-to-one the A end, for one-to-many the B end, for one-to-one the source (A) end, and for many-to-many the source end as a multi-attribute Relationship with one `datasetId` per target. The other end MUST never be stored: it is the query `q={storedSlot}=="{urn}"` on the storing type, which the Portal's grid, forms and assistant issue. The Context Gateway MUST NOT add a computed end to an entity it answers, so every NGSI-LD read stays as CIM 009 defines it.
- **DM-68** [S] — A model MUST be refused at save (the Portal's model source API answers `400` with one `errors` entry per broken rule, naming the slot and the rule, CC-24, DM-56) and at publish (Model Tools refuses generation, DM-18), each refusal naming the slot and the `rule` identifier of [11-data-models.md §1.2](../Architecture/11-data-models.md#12-relationships-between-classes-dm-64dm-73), while any of these stands, each an error and never a warning: a Relationship whose range is not a class of the model or of an import; a class range on a slot that is neither a `Relationship` nor a nested value (a `JsonProperty`, or `inlined: true`, whose class describes the value's shape as the Smart Data Models importer writes `address`); a Relationship whose declared range is a primitive type other than `uriorcurie` or an enum; a Relationship with a class range and no `inverse`; an inverse that does not exist, does not point back, or sits on the wrong class; two relationships sharing one slot as an end; `required` on a computed end (DM-65); an `on_delete` other than the three rules; `on_delete` on both ends of one pair. The editor MUST refuse Save on the same list, and the server MUST NOT trust the editor.
- **DM-69** — A Relationship slot whose range is `uriorcurie`, or that declares no range (the Smart Data Models convention), MUST be read as an external reference: the id of an entity outside this model (a Smart Data Models `refDevice` whose `Device` lives on another platform). It MUST take no inverse, no delete rule and no target check beyond the URN form of CIM 009, the editor MUST show it as an external reference, and it MUST offer to turn it into a relationship when a class of the model or of an import carries the name the reference points at.
- **DM-70** [S] — The Context Gateway MUST refuse, on every write of an Endpoint (create, update, append, replace, upsert and each entity of a batch), a write that breaks a relationship of the space's model, with `400` and the problem type `https://uri.etsi.org/ngsi-ld/errors/BadRequestData`, whose `detail` and the members `slot`, `rule` and `object` name the slot, the rule and the URN: a target that does not exist in the space, a target of another type, a second target on a single end, a missing `required` end, and a one-to-one or one-to-many target another source already stores. The last check MUST be atomic in the store, a unique constraint or a lock and never a read followed by a write, so two concurrent writes cannot both take one target. A batch MUST answer per entity as CIM 009 clause 5.6 says (`207`). The pipeline target, the import, the grid and the assistant MUST write through the same path and MUST NOT check around it.
- **DM-71** [S] — The Context Gateway MUST apply the delete rule of every relationship whose stored end references an entity being deleted, in the same transaction as the delete: `restrict` answers `409` with the problem type `https://joinedcontext.com/errors/relationship-restrict`, the slot and the number of entities still referencing it, and their ids only as far as the caller may read them; `cascade` and `set-null` apply to every referencing entity or none. A refusal of DM-70 or DM-71 MUST NOT name an entity, or carry an attribute value, that the writer may not read.
- **DM-72** — The generated artifacts MUST carry every relationship: JSON Schema, a single end as one Relationship whose `object` matches `urn:ngsi-ld:{Target}:` and a many end as the multi-attribute form with `minItems: 1` when required; SHACL, `sh:class` of the target, `sh:nodeKind sh:IRI`, `sh:minCount` and `sh:maxCount 1` on a single end; the `@context`, `@type: @id`; OWL, `owl:inverseOf` on the pair and `owl:FunctionalProperty` on a single end. Generation MUST stay offline and fetch no IRI (DM-18).
- **DM-73** [H] — A model saved before these rules, with a class-range Relationship and no inverse, MUST be shown by the editor with the refusal of DM-68 and a one-step fix that adds a multivalued inverse slot on the target class: a single-valued slot becomes many-to-one and a multivalued one many-to-many, so the stored end stays the slot that holds the data today and no entity changes. Seeded models MUST be migrated in the batch that enables the refusal, never after it.
