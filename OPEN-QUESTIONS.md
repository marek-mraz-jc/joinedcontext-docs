# Open Architectural Questions & Defensible Defaults

This document tracks unresolved technical questions, edge cases, and external dependency milestones where a defensible default has been adopted in the architecture. Each entry states the current working default and the condition under which it will be revisited.

1. **Gitea 28.0.0 Release Timing & Native Code-Owner Enforcement**: Working default relies on CI status checks to enforce CODEOWNERS approval rules in the interim (stack verdict S2, CC-41); revisit upon Gitea 28.0.0 General Availability to switch to native forge branch protection.
2. **APISIX Standalone Hot-Reload Polling Overhead**: Working default uses APISIX's 1-second file poll interval for `conf/apisix.yaml` ConfigMap reloads (S7); investigate whether the APISIX 3.15+ API-driven standalone mode reintroduces a mutable attack surface before switching.
3. **CUE `vet` vs. Conftest/Rego for CI Metadata Gates**: Working default uses Conftest with Rego for CI manifest validation (CC-59, TS-19); revisit if unifying parameter schemas and validation policies under CUE reduces tooling complexity.
4. **WCAG 2.1 AA Compliance of Complex RJSF Widgets**: Working default adopts `@rjsf/core` with draft-07 schemas (S4); audit custom React autocomplete pickers and dynamic array widgets in Playwright/Axe to ensure no accessibility regressions.
5. **SensorThings API Read-to-Write Evolution**: Working default supports STA v1.1 strictly as a read-only projection over NGSI-LD observations (EP-12, EP-13); evaluate whether write operations (`POST /Observations`) should be supported via gateway translation or redirected to native Bento MQTT ingestion.
6. **Deck.gl 50,000 Feature Rendering Threshold Optimization**: Working default uses a static 50k feature count threshold to switch from native MapLibre GL vector styling to deck.gl WebGL layers (UI-21); benchmark across mobile and low-power organisational client devices to calibrate dynamic thresholds.
7. **Scale-Proofing Regex-Folded Scope Performance at 10M+ Entities**: Working default uses regex-folded scopes in AST rewriting (R13, R41, GW11); execute large-scale PostgreSQL/Antares benchmarks to determine if native `scopeQ` internal header passing (GW24) becomes necessary at high entity volumes.
8. **OpenID Shared Signals Framework (SSF/CAEP) Industry Maturity**: Working default specifies SSF/CAEP Security Event Tokens for cross-FDT policy revocation propagation (R48); verify interoperability with standard external Identity Providers and consider lightweight webhook fallback.
9. **W3C Bitstring Status List Integration with Keycloak**: Working default specifies W3C Bitstring Status List v1.0 for Verifiable Credential status verification (R50); monitor Keycloak upstream extensions and FIWARE VCVerifier plugin releases.
10. **Bento Streams Runner Sharding Threshold**: Working default caps resident streams at 50 per `PipelineRunner` deployment before spawning a secondary runner pod (PL-12); measure real-world memory footprint under heavy transformation loads to optimize density.
11. **LinkML-Map maturity and compiler coverage**: Working default authors model-to-model mappings in LinkML-Map and compiles them to Bloblang (DM-33…DM-39), confining the Python-only, still-young LinkML-Map runtime to authoring time; revisit the supported construct list (DM-36) after the first ten production mappings, and track whether a Rust LinkML-Map implementation appears.
12. **RustFS maturity as default artifact store**: RustFS (Apache-2.0, Rust, S3 API) is young. Working default keeps the platform on the core S3 subset (PF-30) so Garage, SeaweedFS, Ceph RGW or a cloud bucket replace it through the `artifactStore` values block; revisit after the first production deployment and after RustFS' first LTS-style release, and verify object-lock compliance mode in conformance tests (TS).
13. **Gateway mapping IR scope**: live federation and view endpoints translate through a gateway interpreter of the invertible LinkML-Map subset (DM-51, DM-52, EP-54). Working default: renames, value_mappings, linear unit conversion, cast; `expr` read-only. Revisit whether a Rust Bloblang-subset engine would remove the second executor once real cross-city mappings exist.
14. **Ingress controller meshing vs. direct LoadBalancer edge topology**: Working default supports Option A (meshed ingress controller in front of APISIX ClusterIP) and Option B (APISIX LoadBalancer with direct cert-manager TLS). Evaluate whether Option B should become the universal default across all production deployment profiles to eliminate ingress controller dependencies and unmeshed boundary edge cases (`<to verify>`).
15. **Keycloak production brute-force lockout thresholds**: Working default adopts legacy lockout settings (`failureFactor: 10`, `maxFailureWaitSeconds: 900`). Benchmark whether automated API client retries under transient network jitter risk triggering false-positive lockouts, or if APISIX rate-limiting provides sufficient upstream protection (`<to verify>`).
16. **Kyverno Enforce mode rollout strategy on shared enterprise clusters**: Working default deploys cluster-scoped runtime policies with `failureAction: Enforce`. Validate whether pre-configured namespace selectors should be added to prevent admission interference with non-joinedcontext workloads on shared Kubernetes clusters (`<to verify>`).
17. **APISIX standalone configuration pre-apply validation tooling**: Working default relies on `jcctl` internal validation prior to ConfigMap writes. Investigate whether running `apisix -c /path/to/apisix.yaml test` inside an ephemeral container provides additional pre-flight assurance against invalid plugin schemas (`<to verify>`).

18. **Data space connector engine**: closed for the MVP — the connector addon is post-MVP and no engine is chosen (DS-06). The candidates surveyed published no signed image under a vendor or organisation namespace, which DEP-08 requires of everything this platform pulls. Reopen when a data-space partner appears: pick the engine then, against DS-01…DS-03 and the DSP conformance kit, and record it as a new decision.
19. **Builder agent egress allow-list**: the `builder` profile reaches the internet through the platform egress proxy (AG-26). Working default allow-list: `crates.io`, `static.crates.io`, `registry.npmjs.org`, `ghcr.io`, `docs.rs`, `developer.mozilla.org`. Decide who curates the list per organization and whether a per-request approval (MCP elicitation) is offered for hosts outside it.
20. **oauth2-proxy session store for apps**: working default is the encrypted cookie session. Apps with large groups claims or many tabs may exceed cookie limits; decide when to switch a given app to a Redis session store (extra component) and whether the reconciler should choose it from `spec.limits`.

21. **`joins` in the Mapping compiler**: DM-36 lists class-level `joins` on single-valued references among the constructs the Bloblang compiler must support, and DM-38 and [Architecture/11 §7.2](Architecture/11-data-models.md) put joins in the pipeline's own Bloblang. A compiled mapping runs inside one Bento `mapping` processor and sees one message, with no object index to resolve a key against, so the two cannot both hold. Working default: the compiler refuses `joins` with a message pointing at pipeline enrichment or an inline nested object. Decide whether DM-36 drops `joins`, or whether a Mapping may declare an enrichment the reconciler renders as a `branch` ahead of the mapping processor.

22. **Importing a bundle from a URL**: MF-20 names three sources for an import, and one of them is a URL the caller hands to the Portal. There is no egress policy for a Portal-initiated fetch, so honouring it would let any operator make the Portal open a connection to any host reachable from the cluster, the metadata service included. Working default: `POST /projects/{project}/import` answers `501` for `{"url": …}` and accepts the same bundle as an upload. Decide whether the URL source is dropped from MF-20, or whether it is served through the platform egress proxy of item 19 with a per-organisation allow-list.
